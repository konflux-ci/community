# Licensing in Konflux

All repositories within the [Konflux GitHub organization](https://github.com/konflux-ci)
*must* include a `LICENSE` file.

This file should contain the Apache 2.0 license, generated by GitHub, with the
boilerplate `Copyright [yyyy] [name of copyright owner]` replaced, preferably with
the wording `Copyright Red Hat and the collected contributors to Konflux` (notice no
year mentioned).

## New Repositories

All new repositories must be created with Apache 2.0 license.

## Existing non-conforming Repositories

Historically, the organization included mis-licensed repositories. This includes no
license at all, non-Apache-2.0 licenses and licenses with boilerplate copyright
statement.

The following section describes how those licenses and repositories should be addressed.

### License Copyright Line

The format needs to be similar to the one described at the top of this document.
If the repository has either the boilerplate line still present or one which contains
a year, a Pull Request needs to be created to set it to the appropriate format.

### No License or Wrong License

#### MIT License

We should not create new repositories with MIT licenses, but we don't have to relicense
those repositories either.

#### All other Licenses or no License

A Pull Request should be created for fixing or adding the license according to the
specifications above (Apache 2.0 with the mentioned copyright line format).

Red Hat and IBM employees, including subcontractors working on Konflux, that contributed
to the repository being relicensed (at the time of their employment) are not required to
provide consent to the relicensing, but they should comment on the Pull Request if they
know of any reason why the repository should not be licensed under Apache 2.0. The Pull
Request will be open for at least 2 calendar weeks to allow enough time for such
comments to be provided.

All other contributors must provide their consent to the relicensing.

Contributors should object or consent by commenting on the relicensing Pull Request.

In case of no-consent from non-employees, their individual contributions must be removed
from the repo before relicensing (i.e. replaced by an alternative or removed
altogether).

#### Repositories that cannot be Relicensed

If a repository cannot be relicensed it can still be used in Konflux as long as:

1. The module is used in Konflux as a plugin that can be replaced by an alternative.
   I.e. it's utilized via an API through which potential users can plug in an
   alternative. Such alternative doesn't have to exist, but such replacement should be
   possible if it does.
2. All repositories with neither Apache 2.0, nor MIT licenses should be relocated
   outside of the Konflux GitHub organization.
